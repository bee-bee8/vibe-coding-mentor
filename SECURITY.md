# Security Policy

## Reporting a vulnerability

Please do not disclose a suspected vulnerability in a public issue.

Use GitHub's private vulnerability reporting or a private GitHub Security Advisory for this repository when available.

If private reporting is not available, open a minimal public issue stating that you need a private contact channel. Do not include exploit details, secrets, credentials, or sensitive reproduction steps in the public issue.

## What to include

A useful report should include:

- affected component;
- impact;
- reproduction steps;
- relevant environment details;
- proof of concept, if appropriate;
- any suggested mitigation.

Please avoid accessing data that does not belong to you or causing unnecessary disruption while testing.

## Supported versions

Codex Mentor is currently early-stage.

Security fixes are targeted at the latest version of the `main` branch unless a release explicitly states otherwise.

## Scope

Security reports related to local file access, command execution, Codex/App Server integration, sandbox boundaries, dependency risks, or unsafe handling of project data are especially relevant.
